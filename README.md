# Отключаем плашку «Защита от вредоносных программ отключена» в Яндекс Браузере

Мини-инструкция: как навсегда убрать навязчивую плашку в Яндекс Браузере, **не включая** саму «Защиту от вредоносных программ и фишинга» и не закрывая её руками каждый раз.

## Проблема

Если в Яндекс Браузере отключить «Защиту от вредоносных программ и фишинга», то при каждом запуске браузер показывает плашку:

> «Защита от вредоносных программ отключена» — [Включить] (×)

Плашку можно закрыть крестиком, но:

- браузер **не запоминает закрытие** — при следующем запуске она появляется снова;
- это проверено разбором файлов состояния браузера (`Preferences`, `Secure Preferences`, `Local State`): при закрытии плашки не записывается ни один ключ «не показывать больше»;
- включать саму защиту не хочется, а другого штатного переключателя у плашки нет.

## Решение

Через **политику браузера**. Если защита отключена не «личным троганием», а явно управляется политикой, браузер считает это осознанным административным решением и **перестаёт показывать плашку**. При этом сама защита остаётся **выключенной** — мы не включаем сканирование сайтов, только убираем напоминание.

### Способ 1 — .reg-файл (самый простой)

1. Сохраните этот текст в файл `disable-safebrowsing-nag.reg` (кодировка ANSI или UTF-16):

```reg
Windows Registry Editor Version 5.00

[HKEY_LOCAL_MACHINE\SOFTWARE\Policies\YandexBrowser]
"SafeBrowsingProtectionLevel"=dword:00000000
"SafeBrowsingEnabled"=dword:00000000
```

2. Дважды щёлкните по файлу и подтвердите добавление в реестр (появится запрос UAC).
3. Перезапустите Яндекс Браузер.

### Способ 2 — Терминал от администратора

Откройте **Терминал (Администратор)** (`Win+X` → «Терминал (Администратор)») и выполните:

```cmd
reg add "HKLM\SOFTWARE\Policies\YandexBrowser" /v SafeBrowsingProtectionLevel /t REG_DWORD /d 0 /f
reg add "HKLM\SOFTWARE\Policies\YandexBrowser" /v SafeBrowsingEnabled /t REG_DWORD /d 0 /f
```

Затем перезапустите браузер.

### Способ 3 — PowerShell от администратора

```powershell
$root = 'HKLM:\SOFTWARE\Policies\YandexBrowser'
New-Item -Path $root -Force | Out-Null
Set-ItemProperty -Path $root -Name SafeBrowsingProtectionLevel -Value 0 -Type DWord
Set-ItemProperty -Path $root -Name SafeBrowsingEnabled -Value 0 -Type DWord
```

## Что происходит после применения

- Плашка больше не появляется при запуске браузера.
- Сама защита остаётся **выключенной** (в настройках браузера по-прежнему выключена).
- В настройках браузера раздел «Защита» может пометиться как «управляется организацией/администратором», а переключатель станет неактивным — это ожидаемое следствие политики.
- Проверить политику можно по адресу `browser://policy` (в браузере): там видно применённые значения.

## Как вернуть как было

Удалите политику (Терминал от администратора):

```cmd
reg delete "HKLM\SOFTWARE\Policies\YandexBrowser" /f
```

и перезапустите браузер — плашка вернётся.

## Тот же приём для других Chromium-браузеров

| Браузер | Раздел реестра |
|---|---|
| Яндекс Браузер | `HKLM\SOFTWARE\Policies\YandexBrowser` |
| Google Chrome | `HKLM\SOFTWARE\Policies\Chrome` |
| Microsoft Edge | `HKLM\SOFTWARE\Policies\Microsoft\Edge` |

Ключи одинаковые: `SafeBrowsingProtectionLevel = 0` (и при необходимости `SafeBrowsingEnabled = 0`).

## Важно знать

- Политика убирает только напоминание. Она **не связана** с безопасностью сайтов: фильтрация «Защиты от вредоносных программ» по-прежнему выключена, и на сомнительные сайты браузер будет пускать без предупреждений — включите её сами, если почувствуете риски.
- Политика сохраняется между перезагрузками. Удаляйте её только если он перестанет быть нужен.

---

*Инструкция проверена на Яндекс Браузере 26.10 (Windows 10). При тех же симптомах в других сборках должно работать то же самое — политика — штатный механизм Chromium.*
